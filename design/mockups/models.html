What changed.
  1. Split into three pages. One page currently mixes runtime config, a host-daemon lifecycle, a security allowlist, an agent installer and a live console. Splitting makes the dependency chain — host runner → runtime → agent → approved path — visible instead of inferred from card size.
  2. The page called “Models” gets model settings. Today it contains none — model selection lives only in a header dropdown, so the discoverable path leads to a page about Docker.
  3. The dependency chain is shown as a chain. The host runner is the substrate for everything, yet renders below and smaller than the cards that depend on it.
  4. Three agent states, not two. Sandbox currently collapses “not installed”, “daemon down” and “needs login” into one amber “Setup needed” — three problems, three fixes, one label. Direct CLI already does this correctly; this copies it.
  5. Approval says what it grants. Today the words are “Add” and “Approved”, which read as list management rather than granting an AI agent filesystem access.
  6. No bulk approve. “Select all” + “Add” currently approves up to 50 repositories in two clicks with no confirmation — and a partial failure leaves some approved while reporting that nothing worked.
  7. The approved list is visible by default rather than collapsed behind “Show”. A security control users don’t see is one they don’t audit.

Also not visual: revoking access fails silently — it is the one mutation with no error handler, so the row stays and the user cannot tell whether access was actually removed. And the scan root defaults to a hardcoded /Users/navjyotnishant/…, which is broken on every other machine.
