The palette is already in the repo. Every colour above is read from src/globals.css, which already defines a complete .dark block — background 222 47% 11%, cyan primary 190 95% 68%. darkMode: ["class"] is configured in Tailwind and next-themes is in package.json. The foundation was scaffolded and never wired up.
⚠ The real work is 945 hardcoded hex colours. Against only 41 uses of the theme tokens. Those are inline style={{color:"#0f172a"}} and Tailwind arbitrary values like bg-[#fafafa] — neither responds to a theme class, so flipping the toggle today would darken the chrome and leave 945 light-mode colours sitting on top of it.
WorkflowRun.tsx 248 · Workflows.tsx 185 · WorkflowBuilder.tsx 137 · AgentInspector.tsx 77 · Models.tsx 0 — already clean, would go dark almost for free.
Three stages, each shippable.
  1. Toggle, provider, persistence. Mount next-themes, add the switch, respect prefers-color-scheme. Small — and it immediately themes every shadcn component and the Models page.
  2. Convert the four heavy files to semantic tokens. Mechanical but large: #0f172a → text-foreground, #e5e7eb → border-border.
  3. Canvas and node components. React Flow takes explicit colours for edge strokes, background dots and the minimap. Node accents need dark variants too — note the palette above lightens them (#4f46e5 → #818cf8) so they hold contrast on a dark card.

Sequenced as its own epic after the P0 data-loss and authz fixes — those are actively harming users; a theme is not.
