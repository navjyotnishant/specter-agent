What changed.
  1. Split into “My account” and “Users & roles”. Personal credentials currently sit wedged between the create-user form and the account list, under an org-admin heading, splitting admin work in half.
  2. The admin form and Delete buttons are gated on role. Today role is read once — for a badge — so an operator sees the full admin UI, fills it in, and gets a raw backend error. The page’s own copy already says “Admins can create…” while showing the form to everyone.
  3. Delete confirms. One click currently deletes a user account permanently — no dialog, no undo. The highest-risk interaction in the app.
  4. Change role and reset password exist. Neither does today: changing a role means delete-and-recreate, and a locked-out operator has no recovery path at all.
  5. Created and last-seen columns, so an admin can tell a live account from an abandoned one.
  6. Self-service password change on the account tab.

Also not visual: when the users query fails, the page falls back to rendering just the current user, presented identically to a real list — so a 403 looks like “everyone else was deleted”. And delete failures are silent: the mutation has no error handler, so a refused delete leaves the row in place with no message.
